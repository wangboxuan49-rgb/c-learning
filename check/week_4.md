# 第四周验收

- malloc 返回的是 void *，一种「通用指针」，C 里可以隐式转成任何对象指针类型，所以不写强制转换也不会报错；C++ 不允许隐式转换，必须写成 (char *)malloc(...)。

- free(p) 之后 p 里的内容一个字节都不会变，还是原来那个地址，只是那块内存已经还给系统了，这叫悬空指针。访问它属于未定义行为，读出来可能是旧数据、可能是别人的数据，也可能直接崩。

- 所以 p = NULL 必须自己写。free 不会替你置空；手动置空之后，重复 free(NULL) 是安全的空操作，误用会立刻段错误，比静默读写别人内存好定位得多。

- 同一个指针 free 两次叫 double free，是把已经还回去的内存再还一次，会破坏堆管理器的内部记录，属于未定义行为，崩不崩、什么时候崩都不确定。

- calloc(n, size) 有两个参数，而且会把拿到的内存全部置零；malloc 只有一个参数，不清零，里面是垃圾值。要拿数组当计数器用，calloc 能省掉手动清零的循环。

- 内存泄漏是 malloc 之后没有 free，地址丢了，这块内存既访问不到也回收不了，可用堆内存被慢慢吃掉，最终 malloc 返回 NULL 或进程被杀。这跟缓冲区溢出（buffer overflow，写到分配好的内存外面）是两回事，别混。

- C 里的 = 对数组和指针永远只搬地址，从不搬内容。p[j] = temp 是把 temp 数组的首地址存进 p[j]，刚 malloc 出来的那块瞬间没人指向，泄漏；而且所有 p[j] 指向同一块 temp，打印出来每行都一样。复制内容必须用 strcpy(p[j], temp)。

- 反过来，扩容时 p = bigger 是正确的，因为那里要的正是「改指向」：把所有权从旧数组转移到新数组。同一个 =，判断依据只有一句——你想两块内存内容相同，还是想两个名字指同一块。

- 释放顺序不是「按分配时间倒序」，而是依赖倒置：谁里面存着别人的地址，谁就后释放。所以先 for 循环 free(p[k]) 释放每行内容，再 free(p) 释放指针数组本体；反过来先 free(p)，那些行的地址就丢了，全部泄漏。

- 扩容三段式固定为：分配新数组 → 只搬前 count 个指针 → free 旧数组 → p = bigger、cap = newcap。搬的时候上界必须写 count，不能写死 4，否则第二次扩容（cap 已是 8）只搬了 4 个，剩下的全是未初始化指针。

- getchar() 的返回值必须用 int 接，不能写 char ch。EOF 是 -1，无符号 char 存不下，会变成 255，「255 != -1」永远成立，循环永不结束，缓冲区一路被写穿。

- 数组当缓冲区时，下标必须先判断再写，temp[i] = ch 前面要挡一道 i < sizeof(temp) - 1。挡的方式很关键：写满就当一行结束、结算并归零，不能 else continue 直接跳过——那样会把后面判断 '\n' 的结算逻辑一起跳掉，i 卡死在上限，后面所有输入被静默吞掉。

- 末行没有换行符会丢。只在 ch == '\n' 时保存的写法，遇到 printf 'x\ny' 只存到 x；循环结束后要补一段 if (i > 0)，把缓冲区里的残余封口存进去。

- ASan 的几条报错要认得：stack-buffer-overflow 是栈上数组写越界；heap-use-after-free 是释放之后又访问；attempting double-free 是重复释放；LeakSanitizer 的 Direct leak 是指针丢了导致的内存泄漏。每条报错里都标了文件名、行号和涉及的内存区域，先把行号找出来，再问「这行为什么会碰这块内存」。
